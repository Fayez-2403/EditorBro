      How it works

      Three steps, all on the device.

      1. 01

        Agree on a key

        Each phone makes an ECDH P-256 key pair. Swapping only the public halves, both sides derive the same AES-GCM-256 key. The server relays public keys and nothing else.

        deriveKey(ECDH, P-256) → AES-GCM-256
      2. 02

        Seal every message

        Each message gets a fresh 96-bit IV and is encrypted with AES-GCM. The 128-bit tag means any change in transit is detected, so the message is rejected rather than shown.

        encrypt(AES-GCM, iv = 12 random bytes)
      3. 03

        Check the safety number

        A SHA-256 hash over both public keys, shown as twelve five-digit groups. Compare it once in person or on a call to rule out a swapped key.

        SHA-256(pubA ‖ pubB) → 60 digits

      Security notes

      What this demo is, and what it is not.

      Runs
      WebCrypto in this tab. No network calls; the "server" is a panel on this page.
      Private keys
      Generated non-extractable. They cannot be exported and vanish when you close the tab.
      Per message
      A fresh random 96-bit IV, AES-GCM-256 with a 128-bit authentication tag.
      Filming mode
      ?reel=1 imports fixed demo keys and a fixed IV so every frame is repeatable. Never reuse an IV in real use.
      Not covered
      Forward secrecy, key backup, multi-device, metadata hiding. Vaultline is a fictional brand and this is not an audited product.
